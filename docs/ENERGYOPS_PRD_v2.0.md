## 1. 产品定位

EnergyOps 是优先面向园区能源管理专员和能源工程师的能源管理与决策支持系统，结合用能与光伏预测、光储优化和配电网约束分析，并计划接入故障分析与自适应恢复模块，支持能源规划、运行计划制定、故障影响分析与方案复核。目前以校园作为首个验证场景。

### 1.1 产品要解决的核心问题

具备光伏、储能或相关建设计划的园区，在配置和使用能源资源时，需要同时考虑用能需求、费用、碳排与运行约束。项目要帮助用户在明确的数据和假设下比较方案，理解取舍，并形成可审核的决策材料。发生故障时，系统帮助用户了解受影响设备和负荷，查看恢复方案，并根据恢复后的状态调整能源计划。
当前仅通过访谈和现有工作流程梳理，验证能源管理专员和能源工程师使用现有工具时遇到的困难。记录具体任务、使用工具、受阻步骤、人工补救方式及影响；数据整理、方案比较、故障信息核对、恢复结果理解和报告形成是访谈切入点，不预设这些环节一定存在问题。本轮不重新验证核心用户选择，也不评估独立平台使用意愿或采购意愿。

### 1.2 产品能力如何关联

- 预测提供未来负荷和发电的输入。
- 光储规划回答设备如何配置及不同容量的效果。
- 运行优化回答给定设备配置下如何安排购电与充放电。
- 电网与设备检查判断方案是否满足已建模的约束。
- 故障分析识别异常或故障，提供诊断依据与已知影响范围。
- 自适应恢复提供恢复策略及仿真反馈，恢复后的设备状态用于重新计算能源计划。
- Agent 帮助用户表达需求、调用业务工具并理解计算结果。
- 验证、证据和版本记录支持方案复查与复现。

现阶段的产品是决策支持软件。现场自动控制需要另行确认范围，不因接入预测或遥测而自动进入当前交付。

### 1.3 目标园区与进入条件

| 园区类型 | 本版定位 | 适用条件或主要限制 |
|---|---|---|
| 校园 | 首个验证场景 | 已有历史分表数据，实际计量边界与设备配置仍需按现状说明 |
| 办公／研发园区 | 优先扩展的目标场景，未验证 | 集中能源管理，计量及并网边界可识别，能够提供所需设备和用能数据 |

首批目标园区画像：存在统一能源管理责任人，具有光伏／储能资产或建设需求，能明确购电、计量及资产边界，并存在可重复的方案比较或运行计划任务。
未来支持多类园区，不等于首版支持多园区集中运营。当前以单园区分析任务为工作单元。

### 1.4 通用能力与园区配置

| 通用能力 | 园区专属配置／输入 |
|---|---|
| 数据质量与版本管理 | 计量边界、表计倍率、资产身份、时区和粒度 |
| 预测接口与质量校验 | 本园区训练／预测适用范围、负荷特征、天气与预测来源 |
| 光储优化与独立复算 | 装机、储能参数、电价、碳因子、购售电与运行规则 |
| 配电网分析接口 | 网络拓扑、电气参数、节点映射、限值和检查范围 |
| 规划比较与结果解释 | 规划周期、建设条件、成本、退化和财务假设 |
| 故障分析与恢复接口 | 故障样例、资产映射、允许恢复动作、负荷优先级与恢复状态 |
| 报告与审阅 | 管理角色、报告内容、审核责任与可用数据权限 |

新的园区必须经过适用性检查、配置映射和验证。更换地点名称或加载一份新负荷曲线不能证明完成适配；
校园禁止上网、电价、倍率及储能假设不能默认为其他园区事实。

### 1.5 最终成果的分层定义

- 产品成果：一个按园区配置工作的能源管理与决策支持应用，支持规划、运行、故障分析、恢复方案复核与重新规划。
- 首次验证成果：校园案例中可复现的输入、方案、检查报告和用户任务演示。
- 扩展成果：接入模板与适用范围说明；其他真实园区需单独验证。合成园区只可证明接口和配置测试，不等于真实部署成效。
- 待证明的价值：是否帮助工程人员更有效地完成分析，是否让审核者更准确理解取舍和限制；不提前承诺真实节费、减排或采购回报。

### 2.1 团队工作分工

目前项目已有的数据来源仅为科广历史负载数据。已有天气推算光伏、合成碳因子及设备参数假设属于仿真辅助输入，不计作已取得的园区现场数据。

| 工作方向 | 当前可用基础 | 需要补充的内容 |
|---|---|---|
| 调度算法与系统集成（梁紫昱） | 科广负载数据、已有仿真流程与页面基础 | 预测、碳因子、光储配置及电网接口；可先使用明确标注的仿真输入联调 |
| 光伏和负载预测（韦佳伶） | 科广历史负载数据可作为负载预测基础，需按实际时间覆盖和质量划分训练与测试 | 光伏实测或明确的替代建模数据、气象数据及设备信息；光伏实测缺失时不能宣称已验证现场预测准确率 |

## 3. 核心用户任务

| 编号 | 使用时机 | 用户问题 | 期望成果 |
|---|---|---|---|
| J1 | 准备光储建设或改造讨论 | 不同配置对消纳、经济性和电网约束有什么影响？ | 有前提与适用边界的配置比较 |
| J2 | 配置确定后，制定下一日计划 | 依据预测，在费用与碳排目标下如何安排运行？ | 带版本和约束检查的日前计划 |
| J3 | 对方案存在疑问或目标发生变化 | 为什么仍弃光？费用上限变化后结果如何？ | 可追溯解释或重新计算的方案 |
| J4 | 接入遥测后，实际偏离计划 | 偏差是否需要处理？调整有什么影响？ | 偏差说明与新的运行建议 |
| J5 | 发现异常或收到故障事件 | 哪里出现问题，影响哪些设备或负荷？ | 带来源与依据的诊断、影响说明 |
| J6 | 故障后需要恢复供能 | 如何恢复，恢复后原计划是否仍适用？ | 恢复方案、仿真反馈与重新验证的能源计划 |

当前 Demo 首先验证 J3 中的方案比较任务，使用历史研究日场景。J1 的完整规划、J2 的正式预测、J4 的真实反馈尚待建设。J5—J6 作为新增仿真联动任务，先使用高翰林支持的故障案例接入；预设事件只用于接口演示。

## 5. 当前产品基线

以下为已有本地说明与运行产物所记录的校园技术基线；本次文档调整不表示软件或测试结果升级：

- 已完成研究日校园分表负荷整理与质量检查。2026-02-19 完整观测面板有 4,499 台分表，覆盖当日应到资产约 99.08%，不代表校园总表口径。
- 已实现天气驱动的规划光伏推算和三子阵列配置；不是校园光伏实测。
- 当前为 24 个小时点、固定负荷、光伏与储能协调、禁止上网的仿真场景。
- 已有经济、低碳及成本约束低碳目标。阶段 B 汇总有 27 个计划，验证字段全部通过。
- 已实现 Verifier、Evidence、自有 AgentLoop 和五个受限业务工具。
- 既有真实 API 记录：基础循环 completed／2 steps；业务流程 completed／5 steps。业务流程涉及 4 次工具调用，不等于一次调用了全部五个业务工具。
- 本地决策台首版已连接 Agent 服务。实时负荷、实测光伏和实际 SOC 遥测尚未接入；已有历史负载用于离线分析。
- README 记录历史自动化测试结果为 79 passed；本次未复测，不将其视为当前版本的新验收结果。

故障分析与自适应恢复属于待接入模块，已有优化与 Agent 测试不代表该模块已通过验收。当前数据条件以第 2.2 节为准。

现有单日储能容量敏感性分析不等于完整投资规划。已实现的功率平衡和 SOC 检查不等于已完成配电网潮流、电压或保护分析。

## 6. 版本范围与交付阶段

以下 M1—M4 为产品交付里程碑。

| 阶段 | 必须形成的任务能力 | 完成前提 |
|---|---|---|
| M1 可评审 Demo | 历史场景下完成方案生成、比较、追问、验证查看与摘要导出 | 既有计算链路与界面集成完善 |
| M2 运行评估与故障联动 | 正式预测接入与故障恢复仿真两条工作线，分项验收；根据有效状态重新规划 | 预测接口、故障样例、网络参数、恢复方案和反馈接口 |
| M3 光储规划评估 | 长周期或经验证的代表场景下，比较配置效果和约定的经济指标 | 长周期数据、成本与寿命假设、规划目标确认 |
| M4 运行反馈 | 接入真实遥测，开展偏差分析与重调度建议 | 数据接口、设备状态、规则与责任人确认 |

M2 的预测接入与故障仿真可分别推进，故障 Demo 可先采用历史负载回放，不必等待正式预测。M2 与 M3 可根据协作方交付情况并行准备。规划和运行分析应共享资产、输入版本与约束定义，避免同一设备在不同模块使用冲突参数。
本版暂不承诺：现场自动控制、继电保护整定、现场故障自动处置、多园区统一运营与多租户计费、生产级可用性，以及基于单日仿真的真实年度收益。

## 7. 功能需求与验收行为

“已有基础”仅表示存在实现或产物，不代表下列完整用户流程已经验收。

| ID | 阶段／现状 | 需求 | 验收行为 |
|---|---|---|---|
| FR01 | M1／已有基础 | 场景与输入说明 | 显示数据边界、日期、时区、粒度、设备配置、输入类型和缺失项；实测、预测、合成、规划假设可区分 |
| FR02 | M1／已有基础 | 目标表达与参数确认 | 自然语言或表单形成同一结构化请求；运行前可见目标与费用增幅等参数；歧义或缺参时先澄清 |
| FR03 | M1／已有基础 | 已验证方案生成 | 质量门、优化与独立复算不可跳过；失败时显示原因，不显示伪成功计划 |
| FR04 | M1／已有基础 | 方案比较 | 同条件目标比较要求同输入版本；容量比较明确标出唯一变化的设备参数，其余外生输入保持一致；条件不同不得伪装成同口径比较 |
| FR05 | M1／已有基础 | 结果解释与证据查看 | 关键数字关联计划与证据；点击可见指标、时间范围、来源版本及约束结果；追问改变条件时重新计算 |
| FR06 | M1／待完善 | 结果展示与刷新 | 新计划完成后自动更新对应图表和指标；显示当前计划 ID，避免新解释搭配旧曲线；无需手动重新构建页面 |
| FR07 | M1／待完善 | 保存、导出与审核 | 导出含场景、方案差异、验证范围、假设与限制的摘要；区分待审核、已审阅、需修改；审阅不触发控制 |
| FR08 | M2／待接入 | 负荷与光伏预测 | 校验发布时间、有效期和预测窗口；过期或缺失按明确策略阻断；无真实观测时不显示已验证的预测准确率 |
| FR09 | M2／待接入 | 配电网安全分析 | 返回通过、不通过或无法评估，并标明检查范围；数据不足不得视为安全；越限时提供位置、时段与依据 |
| FR10 | M3／仅有容量敏感性基础 | 光储规划 | 对指定配置或约定搜索范围开展长周期评估；保存容量、气象负荷、经济参数和模型版本；无投资数据时只输出技术指标 |
| FR11 | M4／仅有界面和规则骨架 | 偏差与重调度 | 对齐计划和实测；缺数据保持未接入；达到约定规则后提出重算建议；新方案重新验证并关联原方案 |
| FR12 | M1／新增需求 | 园区配置与能力声明 | 显示园区 ID、配置版本、资产／计量边界及可用模块；校园配置作为首个实例；未实现模块显示未接入 |
| FR13 | 扩展前／新增需求 | 新园区接入检查 | 校验单位、时区、映射、电价、并网和网络数据；缺少关键输入时阻断相关能力，不沿用校园默认值 |
| FR14 | 扩展前／新增需求 | 园区与版本隔离 | 场景、计划、预测、证据和报告关联园区 ID；已有证据不随配置覆盖；Agent 不得混用不同园区的结果 |
| FR15 | M2／待接入 | 故障分析与影响展示 | 显示事件时间、来源、故障类型、受影响资产及依据；模拟事件明确标识，缺少映射时不推断完整影响 |
| FR16 | M2／待接入 | 恢复方案与反馈 | 展示动作、前提、仿真状态和剩余故障；生成方案不等于恢复成功 |
| FR17 | M2／待接入 | 故障后重新规划 | 依据有效恢复反馈或明确标注的假设分支更新设备状态，重新优化并验证，新旧计划保留关联 |
| FR18 | M2／待接入 | 事件报告 | 串联故障、恢复方案、状态反馈和新计划，说明检查范围与未恢复部分 |

FR12 的配置展示可以先覆盖一个校园实例；FR13—FR14 须在首次非校园数据导入前验收。多园区账户、租户权限、组合运营与计费平台不在本版交付范围。
比较口径特别说明：经济方案与成本约束低碳方案比较时，费用指标与增幅基线必须一致。纯经济差异不能归因为容量变化；跨版本结果应显示差异原因。

## 8. 产品模块设计

本节定义目标模块及协作接口，不代表新增能力已经实现。当前实现依据第 5 节记录；正式预测、碳因子与设备数据、电网及故障恢复模块按后续交付接入。

### 8.1 负荷与光伏预测模块｜韦佳伶

**用途**：为日前调度提供同一时间窗口下的用电需求与光伏发电预测。

| 设计项 | 内容 |
|---|---|
| 输入 | 历史负荷、计量边界、预测窗口与时间粒度；光伏预测另需气象、装机及相应建模数据 |
| 处理 | 检查缺失和异常，按时间划分训练与测试，分别生成负荷、光伏预测并记录模型版本 |
| 输出 | 带时间戳与单位的预测曲线、发布时间和有效窗口、数据与模型版本、质量说明及误差报告 |
| 页面 | 展示预测曲线、来源、有效期和质量状态；有对应实测时展示预测与实际的偏差 |
| 对接 | 向梁紫昱提供调度输入；从凌俊楷提供的配置中读取光伏装机参数 |
| 验收 | 时间与单位可对齐，缺失／过期结果可识别；误差报告说明测试时段、指标与比较基线，不能用训练集效果代替测试效果 |

**当前基础**：仅科广历史负载可用于负荷预测研究，具体可用样本按覆盖与质量检查确定。光伏与气象输入尚需补充；天气推算曲线只能作为标注清楚的仿真输入，不能作为现场光伏预测准确率的证明。

### 8.2 碳因子与光储参数模块｜凌俊楷

**用途**：为低碳目标提供计算依据，并把校园光伏装机与储能配置整理成可复用的场景参数。

| 设计项 | 内容 |
|---|---|
| 输入 | 碳因子计算所需源数据、适用区域与时间范围；校园光伏装机资料、储能规格及运行参数 |
| 处理 | 计算或整理碳因子序列，统一时间粒度与单位；核对装机、储能功率／容量、效率、SOC 范围和初始状态，区分资料值与假设值 |
| 输出 | 碳因子序列及来源、方法和版本；光伏装机与储能参数包、参数依据和缺失清单 |
| 页面 | 在场景配置中展示装机、储能和碳因子，标注数据来源与假设；方案结果展示相同口径下的碳排估算 |
| 对接 | 光伏参数交给韦佳伶用于预测；碳因子与光储参数交给梁紫昱用于调度及方案比较 |
| 验收 | 碳因子单位与计算边界明确，适用窗口覆盖分析时段；设备参数自洽，缺失值不默认为零，修改后生成新版本 |

**当前基础**：尚无正式碳因子源数据和现场光储设备资料，现有合成碳因子及设备假设仅供仿真。碳排结果应附计算口径，不作为正式减排认定。该模块提供参数与依据，不承担运行调度算法或自动容量寻优。

### 8.3 调度算法与系统集成模块｜梁紫昱

**用途**：把用户目标和专业模块输出转化为可比较、可解释、可复核的能源计划，并完成产品 Demo。

| 设计项 | 内容 |
|---|---|
| 输入 | 历史回放或预测负荷／光伏、碳因子、电价、光储配置、运行约束及用户目标；故障后增加有效的设备可用状态 |
| 调度算法 | 支持经济、低碳和成本约束低碳目标，计算购电、光伏利用／弃光、储能充放电与 SOC；由独立 Verifier 复算指标与约束 |
| Agent 流程 | 将用户需求整理为明确参数，调用计算、验证、比较及查询工具，依据结果解释取舍；数值由专业模型和程序计算 |
| 页面与交互 | 串联场景选择、参数查看、目标输入、方案比较、依据查看、故障恢复及报告导出；展示过程状态、失败原因和数据版本 |
| 输出 | 调度计划、费用与碳排估算、功率／SOC 曲线、独立验证结果、证据记录和方案报告 |
| 系统接入 | 接收韦佳伶的预测与凌俊楷的碳因子／设备参数；对接高翰林的电网检查与恢复反馈，更新可用资源后重新规划 |
| 验收 | 同口径比较方案，关键数字可追溯；输入缺失、不可行或验证失败时明确阻断；恢复后新计划使用新状态并重新验证 |

**流程**：核验输入与版本 → 调度求解 → 独立验证 → 调用电网检查 → 展示结果与检查状态 → 解释、比较与导出。电网模块尚未接入时，保留已完成的设备约束结果并标注网络检查未完成，不显示“电网安全通过”。后置电网检查不通过时，方案保留为分析记录；有已定义调整规则时重算，否则交工程人员处理。

**当前基础**：已有优化、Verifier、Evidence、AgentLoop 和页面基础；本次分工不意味着新增模块已经接通。后续完成正式输入接入和故障恢复联动，完整规划经济评估仍按单独需求推进。

### 8.4 电网分析与故障恢复模块｜高翰林

- **电网分析**：检查购电功率、SOC、设备容量和防逆流，以及潮流、节点电压、线路及变压器过载。
- **故障分析**：接收故障诊断结果，展示故障类型、受影响设备及相关依据，定位和影响范围按模型实际能力呈现。
- **自适应恢复**：展示恢复策略与仿真反馈，将更新后的设备状态用于后续能源计划。

高翰林负责专业模型与验证，梁紫昱负责 EnergyOps 数据对接、页面展示、Agent 解释和流程集成。

| 环节 | 输入 | 输出 |
|---|---|---|
| 电网检查 | 网络与设备参数、负荷、能源计划和运行约束 | 检查状态、越限信息及依据 |
| 故障分析 | 设备测量、状态或明确标注的仿真故障样例 | 故障事件、诊断结果、已知影响范围 |
| 恢复仿真 | 故障事件、可用资源、限制和允许动作 | 恢复方案、仿真反馈、剩余故障及设备状态 |
| 重新规划 | 有效恢复状态、负载及其他调度输入 | 新的能源计划、验证结果和变化说明 |

各环节关联同一园区、事件和状态版本。重复或过期事件不能覆盖有效状态。检查失败、数据不足或没有恢复反馈时，页面明确标注失败／未知，不宣称恢复成功。

**产品边界**

本版以仿真联动接入，Agent 解释专业模块结果，不执行真实设备指令。恢复建议、仿真完成与实际恢复分别标记。优化验证、电网检查和故障恢复验证分别展示，小时级能源计划不作为故障瞬间动态稳定性的证明。

### 8.5 模块协作与交付

正常运行：凌俊楷提供碳因子与光储配置，韦佳伶提供预测，梁紫昱生成调度计划并独立验证，高翰林提供电网检查，结果统一进入方案比较与报告。
故障联动：高翰林提供诊断、恢复方案及仿真反馈，梁紫昱依据有效恢复状态更新场景、重新调度并提交检查。恢复建议本身不视为设备状态已改变。

各模块使用统一的园区标识、时区、时间粒度、分析窗口及版本引用，交付输入输出样例和测试依据。梁紫昱负责对齐接口与联调；各模块负责人解释专业结果及适用限制。模拟样例接通与专业算法验证分别记录。

## 10. 产品流程与页面

### 10.1 M1 主流程

选择场景 → 查看输入与假设 → 表达目标 → 确认参数 → 计算与验证 → 比较方案 → 追问并查看依据 → 导出／审阅。
每一步均明确当前计划和数据版本。页面支持从失败原因返回参数或数据准备步骤。

### 10.2 故障分析与恢复流程

接收事件、展示诊断与影响、获取恢复方案、运行仿真、接收状态反馈、更新场景、重新优化与验证、导出事件报告。恢复建议尚未获得反馈时，仅可基于明确假设进行分支分析，不覆盖当前运行状态。

### 10.3 页面结构

| 区域 | M1 内容 | 后续扩展 |
|---|---|---|
| 场景与目标 | 园区标识、研究日、容量、目标、边界和假设 | 预测窗口、网络模型、规划周期 |
| 方案结果 | 对比指标、功率与 SOC 曲线、约束结果 | 网络越限、预测误差、规划经济指标 |
| 分析助手 | 示例问题、追问、解释与关键证据入口 | 故障与恢复结果解释、跨版本变化说明 |
| 故障与恢复 | 待接入 | 事件列表、诊断依据、影响范围、恢复方案与反馈、新计划入口 |
| 证据详情 | 输入版本、Verifier、Evidence、必要的 Trace 摘要 | 电网报告及预测质量记录 |
| 报告与审阅 | 保存、导出、审阅意见 | 计划与实际对比报告 |

默认呈现业务结果，工具名和调用详情放在证据区域。只有分析负责人需要的设置才进入高级选项。

### 10.4 状态定义

- 正在检查数据、计算中、验证中：过程状态。
- 验证通过、待人工审阅：仅代表指定模型和检查范围通过。
- 数据不足、不可行、检查失败、调用失败：分别说明原因和下一步。
- 已审阅／需修改：人的处理记录，与计算通过状态分开。
- 故障诊断：有故障、无故障或无法判断，按模块输出显示。
- 恢复仿真：待运行、运行中、完成、部分恢复、失败或无反馈。方案生成不等于恢复完成。

底层已有 pending_human_approval 和 safe_terminated 状态。新增审阅记录需明确映射，不借此产生设备执行权限。

## 11. 非功能与可信性要求

- 可复现：保存输入、模型与参数版本，使用同一口径复算指标；允许求解器在多最优解下返回不同但同样有效的计划。
- 数值正确性：功率、能量、SOC 和费用等误差阈值由模型负责人按单位和求解精度定义，版本化配置后用于验收。
- 交互一致性：解释、图表、导出摘要必须指向同一计划。失败或超时后可查看状态，不用旧结果充当新结果。
- 可恢复：设置可配置的调用、求解与总任务预算；重复点击不产生含混结果；重试保留关联记录。
- 权限与数据：Agent 使用业务工具白名单；密钥不进入前端、导出或 Trace；报告不包含不必要的原始分表敏感信息。
- 运行边界：本版保持 simulation_only=true、executable=false；人工审阅不解除这一限制。
- 性能：记录端到端时间、求解时间与模型调用成本，先建立基线，再由团队确定目标，不预先声明未测量的速度提升。

## 12. 验收与评估计划

### 12.1 M1 必测用例

| 编号 | 用例 | 通过条件 |
|---|---|---|
| AT01 | 生成经济与成本约束低碳方案 | 输入口径一致；约束与指标独立复算通过；费用增幅相对指定经济基线计算 |
| AT02 | 比较已有三档储能 | 清楚显示容量变化；其余输入一致；不输出无依据采购结论 |
| AT03 | 追问弃光原因 | 数值有对应证据；区分计算事实和推断；不凭解释擅自生成新结果 |
| AT04 | 缺少低碳目标所需碳因子 | 停止该目标计算，说明缺失项；不把零碳排或经济方案冒充低碳结果 |
| AT05 | 计划篡改、不可行或验证失败 | 返回失败并保留原因；不发布为已验证方案 |
| AT06 | 参数或输入版本变化 | 生成新计划并标出变化；界面、解释和导出同步 |
| AT07 | 模型调用失败／超时 | 显示失败或明确的只读回退，不能声称已完成新的 Agent 分析 |
| AT08 | 导出与人工审阅 | 摘要包含范围、版本、假设和证据；审阅不触发设备执行 |

这些是拟定验收用例，不代表已经全部通过。异常演示使用单独测试样例，不篡改原始数据。

### 12.2 后续能力验收

- 预测：覆盖时间对齐、过期、缺失、版本切换；准确率仅在有对应实测时评估，并与指定基线比较。
- 电网：覆盖正常、越限和数据不足样例；由高翰林给出可信参考模型或已知结果，并说明所验证的工况。
- 规划：统一比较周期、成本口径和基线；验证敏感性与长周期结果；不得把单日收益简单乘以天数作为年度结论。
- 遥测：验证迟到、缺失、时间错位及偏差持续时间；重新生成的建议必须再次计算与验证。

### 12.3 园区适配验收

| 编号 | 用例 | 通过条件 |
|---|---|---|
| AT09 | 配置化改造后的校园回归 | 同配置输入下指标在约定容差内一致；允许多最优解；原有验证与证据链不丢失 |
| AT10 | 新园区字段缺失或映射错误 | 明确缺失／不匹配项，阻断受影响计算；不自动继承校园关键参数 |
| AT11 | 两个测试园区的计划与证据引用 | 报告、解释和比较均指向正确园区；跨园区调用被拒绝或明确提示不属于同场景比较 |
| AT12 | 非校园案例迁移验证 | 单独记录模型是否变更、数据依据、结果参考和适用限制；完成后才能声明该类案例已验证 |

AT09 为 M1 配置化需求验收；AT10—AT11 在新园区导入前完成。AT12 需要实际获得第二场景的数据与参考结果，未满足时保持“待验证”。园区配置通过并不能代替电网模型或预测模型的适用性验证。

### 12.4 故障分析与恢复验收

| 编号 | 用例 | 通过条件 |
|---|---|---|
| AT13 | 正常、故障及无法判断样例 | 诊断状态与参考结果可核对，模拟来源可见，缺数据不显示健康 |
| AT14 | 缺映射、重复或过期事件 | 标注影响范围未知，维护正确园区与状态版本，不重复生成冲突记录 |
| AT15 | 恢复完成、部分恢复、失败或无反馈 | 状态与反馈一致，列出未恢复部分，不凭方案生成声明恢复成功 |
| AT16 | 恢复后重新规划 | 使用更新后的可用资源与限制，新计划独立验证并关联原计划 |
| AT17 | 恢复或重规划失败、Agent 解释与导出 | 正确提示失败，数字和状态可追溯，全程不下发控制 |

接口联调与算法验证分别记录。高翰林提供故障与恢复参考样例、成功判据及模块测试，梁紫昱验证页面、状态流转和新计划衔接。检测误报／漏报、恢复时间及缺供电量仅在有对应数据与评价口径时报告，不将仿真结果写成现场效果。

### 12.5 当前用户研究：现有工具的困难

研究对象为能源管理专员和能源工程师。请受访者结合最近一次真实任务，说明使用了什么工具、在哪一步遇到困难、如何处理，以及对工作产生了什么影响；可结合脱敏表格、报告或操作过程核对。
本轮产出为现有工具问题清单：按具体任务归纳困难，保留实例依据和影响，区分已确认问题与尚无实例支持的推测，并形成需求优先级建议。不将使用意愿、采购意愿、产品效果对比或核心用户重新选择列为本轮验证项。

### 12.6 后续产品效果评估（不纳入当前用户研究）

以下指标留待功能完成后的产品试用和技术验收阶段使用：

| 指标 | 测量方式 | 目标状态 |
|---|---|---|
| 典型任务完成率 | 用户能否完成方案比较并回答指定决策问题 | 完成用户基线试验后确定 |
| 任务时间与操作步骤 | 同一数据任务，对比现有脚本／表格流程与产品流程 | 不预先承诺改善比例 |

单日仿真结果、测试通过数和 API 跑通不能代替用户价值或真实节费验证。

## 13. Demo 与最终交付

### 13.1 Demo A：正常方案比较

用户任务：“比较经济与低碳方案，在费用最多增加 5% 的情况下优先减碳，并解释为什么仍有弃光。”
演示顺序：

1. 说明产品面向园区，当前演示使用校园案例；显示园区、研究日、设备配置及实测／假设边界。
2. 输入目标并展示结构化参数。
3. 生成、验证并比较方案，展示指标与曲线。
4. 追问弃光原因，打开关键证据。
5. 比较另一档储能，明确其为容量敏感性分析。
6. 使用单独缺数据样例展示阻断行为，最后导出有效方案摘要。

未接入的预测、网络分析、故障恢复与遥测用后续路线说明，不能用界面占位表现为已完成。

### 13.2 Demo B：故障分析与恢复仿真（待接入）

1. 展示校园历史负载场景及原运行计划。
2. 注入高翰林支持的一种仿真故障，展示诊断和已知影响范围。
3. 接收恢复策略，展示其前提、动作与检查结果。
4. 获取仿真反馈，区分恢复完成、部分恢复或失败。
5. 根据反馈后的设备状态生成并验证新计划，解释与原计划的差异。
6. 导出事件报告，保留故障、恢复与计划的关联依据。

只有预设事件时标为接口演示，不作为故障检测效果证明。无可行恢复策略时展示限制与失败原因，不预设必然恢复成功。

### 13.3 预期最终交付

- 可完成所确认任务的 EnergyOps 园区能源管理与决策支持应用，以校园案例作为首个验收对象。
- 园区配置模板、能力适用说明和新园区接入检查清单；跨园区验证结果仅在实际完成后交付。
- 预测、碳因子与调度、电网分析、故障恢复及规划模块的接口与数据契约。
- 故障与恢复页面、仿真案例、事件报告和恢复后重新规划记录。
- 可复现的正常和异常场景、基线对比、验证报告。
- 现有工具困难调研记录与问题清单；后续功能完成后再形成方案报告样例与用户试用反馈。
- 部署使用说明、边界说明、已知问题及 Roadshow 演示材料。

各阶段验收后再决定是否进入下一阶段；完整最终范围以团队确认的需求清单为准。

### 13.4 新园区扩展流程

1. 确认园区类型、用户任务和模型适用范围。
2. 核验数据授权、计量边界、资产配置和并网规则。
3. 建立新园区配置及预测／网络模型映射。
4. 运行配置检查与已有参考案例对比，必要时调整模型。
5. 由业务与模型负责人确认适用范围，记录未支持的工况。
6. 只有完成验证才将该园区标记为可用于对应任务，不据此推及所有同类园区。
